# 发布清单

版本：app `0.8.17-beta.26`，引擎 `v0.35.10`。

## 1. 这一版改了什么

beta.26 相对 beta.25（引擎 v0.35.9 → v0.35.10）：

- 技能只按"给了谁"算：通用子 agent 不再暗中带上主 agent 的技能，能力 → 技能里每段只列给了这个 agent 的技能。数据库迁移 0028 把主 agent 已有的技能都补给通用子 agent，升上来后各 agent 看到的技能不变。
- 主 agent 的规则写明什么时候派子 agent 划算（要读的东西会塞满会话时派探索、几件互不相干的事同时做、做完让验收换双眼睛看、长任务），小事自己做，任务要写清目标、做完的样子、别碰什么、报告要有什么。
- 三个子 agent 共用一套工作和安全规则；会用浏览器的角色（主 agent、通用、探索、验收）都有同一段浏览器规则，验收子 agent 也知道遇到登录或提交前要停。通用子 agent 的报告写明改了什么、在哪、跑了什么验证、结果如何。子 agent 到上限时把报告写给派它的 agent。
- 协议：技能去掉 `heldBy`。要配 v0.35.10 的 ollupid。

beta.25 相对 beta.24（引擎 v0.35.6 → v0.35.9）：

- 子 agent 只剩三个，按能做什么分：通用子 agent 动手做事；探索子 agent 查项目、网页和浏览器，只读，每个结论给出处；验收子 agent 按标准构建、跑测试、亲手试，只报告不修。浏览器、设计、代码库、前端、后端、写作、研究子 agent 都去掉了，它们各自的做法并进主 agent 和通用子 agent 的规则。
- 派子 agent 的调用行：探索子 agent 用放大镜图标、标"只看不改"，验收子 agent 用清单图标、标"只查不改"。
- 能力 → 技能：每个 agent 一段，编辑技能时可勾的 agent 只剩主 agent、Super Agent、通用、探索、验收。
- 已结束的轮次里，工具输出在之后的请求中最多留 512 token（原来最多 6000），要看全文用 `read_tool_output`；当前这一轮不变。
- 数据库迁移 0026：已有会话、轮次、排队消息里的旧子 agent 角色改成通用（浏览器、设计、前端、后端、写作）或探索（代码库、研究）；给旧子 agent 的技能改给主 agent（通用子 agent 也就有了）或探索子 agent。
- 数据库迁移 0027：历史里派旧子 agent 的调用也改成对应的新工具名，升上来后这些调用行照样显示任务，能打开子 agent 会话。
- 协议：角色列表和派子 agent 的工具换成 `general-sub-agent`、`explore-sub-agent`、`verify-sub-agent`；要配 v0.35.9 的 ollupid，更早的不兼容。

beta.24 相对 beta.23（引擎 v0.35.5 → v0.35.6，只改提示词，协议不变）：

- Super Agent 的待办工具说明写明上下级只记在 `parent` 里：把待办挪到另一个下面时，不再往标题或备注里写"挪到了某某下"；备注只写要做什么、在等什么。
- 交给子 agent 的活归它，直到报告回来：主 agent 派出子 agent 后只做子 agent 不管的事，不再自己把同样的任务重做一遍，依赖报告的部分等报告回来再写。

beta.23 相对 beta.22（引擎 v0.35.4 → v0.35.5）：

- 能力页按 agent 分开看：技能、MCP、内置工具三页都把主 agent、Super Agent 和各个子 agent 从上往下分段列出，每段标出数量。同一个技能、同一台 MCP 服务器在每个有它的 agent 下各出现一次，改它所有 agent 都变。
- 只有主 agent、Super Agent 和通用子 agent 用得到 MCP；其余子 agent 那一段写"用不了 MCP 服务器"。
- 内置工具每组一张卡片，按行两张一排、同一行一样高，展开的那组独占一行。
- 修复："帮手"一组显示成原名 `subagents` 并排在最后；`deferred_tools` 现在叫"载入工具"。
- 协议：`tool/list` 的每个工具、`mcpServer/list` 和 `mcpServer/changed` 的每台服务器多了 `roles`，列出有它的 agent。

beta.22 相对 beta.21：

- 待办面板按层级显示：子待办缩进在上级下面，沿一条细线排开；上级在另一组或归档的另一个月时，子待办留在本组顶层，写"属于「上级」"。
- 修复：启动后归档是空的（只请求了没结束的待办），现在一打开就能看到做完和放弃的。

beta.21 相对 beta.20（引擎 v0.35.3 → v0.35.4）：

- 待办可以挂在另一个待办下面，最多三层；Super Agent 用 `parent` 记上下级，不再写进标题或备注。桌面的待办面板这一版仍是平铺列表，还不显示层级。
- 数据库迁移 0025：`todos` 加 `parent` 列，已有待办都在顶层。

beta.20 相对 beta.19（引擎 v0.35.2 → v0.35.3）：

- Super Agent（中枢）把互不依赖的调用放在同一次回复里发出，比如列会话、读会话同时进行，不再每个都多花一次模型调用。

beta.19 相对 beta.18（引擎 v0.35.1 → v0.35.2）：

- 协议：正文和思考的流式文字合并成一个 `item/delta` 通知，用 `type` 区分；桌面端跟着改，界面上看不出差别。和 v0.35.1 及更早的 ollupid 不再兼容（收不到流式文字）。
- 定时任务：已归档会话里过期的任务不再挡住别的任务，活跃会话的任务不会再晚最多一分钟才跑。
- 在线时长：按天、工作区、待办分组时不再把在别的应用里的时间算进来。
- 思考条目的结束时间按答案开始流出的时刻算。

beta.18 相对 beta.17：

- 设置改成一整页：各分类依次排下来，每节一个标题和一句说明；左边的分类跟着滚动标出当前所在的一节，点一下滑过去。
- Super Agent 由后端建：点「开始」后，后端在第一个环境旁边的 `super-agent` 文件夹建好中枢（本机就是原来的 `~/.ollupi/super-agent`，已有的中枢不动）；桌面端不再自己算路径、建文件夹，连远程 ollupid 也能开始。别的工作区不能再改成中枢，中枢的文件夹不能移动。

beta.17 相对 beta.16：

- 环境改在设置里管理：新增「环境」页（在「连接」后面），新增、改名、删除环境都在这里；草稿页的环境选择器只用来选新会话在哪个环境跑，不再有"管理环境…"。

beta.16 相对 beta.15（设计见 [workspace-environment-design.md](workspace-environment-design.md)）：

- 每个会话都属于一个工作区：不选项目开的会话放进所在环境的"默认工作区"（scratch 工作区，就是环境自己的文件夹），在侧边栏底部；记忆里不再有"无工作区"这一类，原来的记忆归到默认工作区。
- 文件面板、Git 改动、终端都由后端在工作区所在的环境里执行，不再读这台 Mac 的路径：连远程 ollupid 时这些面板也能用。
- 终端由后端开，经 WebSocket 连过来：关掉面板或窗口后继续跑，再打开显示最近的输出；完全访问，但读不到 `~/.ollupi/data`。
- Git 以人的身份跑（完全访问）；丢弃没提交过的文件移到废纸篓。
- 添加工作区改成弹窗里浏览环境机器上的文件夹（可新建）；移动工作区文件夹在工作区设置里浏览。
- 附件先上传给后端，再在消息里引用。
- 去掉工作区文件的"在访达中显示"和"用默认应用打开"。
- 数据库迁移 0024：给每个环境建默认工作区，没有工作区的会话和"无工作区"的记忆挪进去，删掉 `threads.environment_id`。这一步不可逆，装回 beta.15 读不了新库。

beta.15 相对 beta.14：

- 侧边栏底部改成两行：上一行是平台的模型、用量、能力，下一行是自己的记忆、定时任务、设置；定时任务不再在顶部。
- 模型和用量从设置里拆出来，各是一页；设置只剩这个身份自己的。
- 更新器清理下载目录改用 `rm -rf`。

## 2. 引擎

sidecar 钉在 `v0.35.10`：

```bash
grep 0xfakeSpike/ollupi ~/Desktop/yiming/ollupi-desktop/sidecar/go.mod
ls ~/go/pkg/mod/github.com/0xfake\!spike/ollupi@v0.35.10/store/sqlite/migrations/ | tail -2
```

## 3. 打包

```bash
cd ~/Desktop/yiming/ollupi-desktop
pnpm release
```

打完确认二进制是新的（第一行要是 v0.35.10，后两行 0 就是没进去）：

```bash
go version -m apps/desktop/release/mac-arm64/Ollupi.app/Contents/Resources/bin/ollupid | grep 0xfakeSpike/ollupi
grep -ac 'mcpServer/list' apps/desktop/release/mac-arm64/Ollupi.app/Contents/Resources/bin/ollupid
grep -ac 'terminal/open' apps/desktop/release/mac-arm64/Ollupi.app/Contents/Resources/bin/ollupid
```

## 4. 发到 GitHub

```bash
gh release create v0.8.17-beta.26 --prerelease --title "0.8.17-beta.26" --notes-file notes.md <dmg> <zip> latest-mac.yml
```

## 5. 装完自查

- 升上来之后打开一个以前派过研究或浏览器子 agent 的会话：调用行和子 agent 会话都还能打开。
- 让主 agent 查一件事：派的是探索子 agent，调用行有放大镜和"只看不改"；让它做完后验收：派验收子 agent，标"只查不改"，它不改文件。
- 能力 → 技能：只有主 agent、Super Agent、通用、探索、验收五段；升上来后原来主 agent 的技能在通用子 agent 那段也有（迁移 0028 补的）；新建一个只给主 agent 的技能，通用子 agent 那段没有它。
- 让主 agent 改一处代码并验收：通用子 agent 的报告写了改了哪些文件、跑了什么、结果；验收子 agent 碰到登录页会停下来问。
- 在一个长会话里读过大文件后再发一句话：回答正常，需要时它用 `read_tool_output` 去读。
- 让 Super Agent 把一个待办挪到另一个下面：备注里没有"挪到了…"之类的记录。
- 让主 agent 同时派两个探索子 agent（一个查网页、一个看代码）：等两份报告回来再写结论，自己不重做它们的任务。
- 能力 → 技能：每个 agent 一段；给一个技能多勾一个 agent，它在两段下都出现。
- 能力 → MCP：主 agent、Super Agent、通用子 agent 下有服务器，探索和验收子 agent 写"用不了 MCP 服务器"。
- 能力 → 内置工具：每行两张卡片；展开一组，它独占一行，旁边的卡片补上来；"帮手"和"载入工具"都有中文名。
- 让 Super Agent 把一个待办拆成几个子待办：面板里子待办缩进在上级下面，标题里不带上级，原有待办都还在。
- 重开应用后打开待办面板，归档里有以前做完的待办。
- 让 Super Agent 列出并读几个会话：同一轮里一起调用，不是一个接一个。
- 发一条消息：思考和回答都一个字一个字流出来，结束后和重开会话看到的一样。
- 设置：从上滚到下，左边的分类跟着走；点「权限」滑到最后；侧边栏的设置按钮打开在「身份」。
- 没有 Super Agent 的身份点「开始」，`super-agent` 文件夹建在环境文件夹旁边；已有的中枢照常打开。
- 设置 → 环境：新增一个环境、改名、删掉；草稿页的环境选择器里没有"管理环境…"。
- 升上来之后：工作区、会话都在；原来不属于工作区的会话在侧边栏底部的"默认工作区"里。
- 添加工作区：弹窗里浏览文件夹、新建文件夹、添加。
- 文件面板看 Markdown（相对路径的图片能显示）、PDF；环境面板暂存、提交、丢弃一个新文件（进废纸篓）。
- 终端：关掉面板再开，之前的输出还在；`cat ~/.ollupi/data/store.sqlite` 被拒。
- 发一张粘贴的截图和一个拖进来的文件。
- 连远程 ollupid（同为 v0.35.10）时，上面这些面板都能用。

## 这版的已知限制

- 还没接任何云沙箱，提供方只有这台电脑。
- 身份不是本机上的安全边界：同一 macOS 账户下，各身份的文件互相可读。
- API key 仍明文存在数据库里（沙箱里的命令读不到数据库）。
