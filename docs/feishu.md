# 飞书机器人

在手机上通过飞书（或 Lark）机器人操作 Ollupi 的会话。机器人跑在 sidecar 里，用长连接主动连到飞书，Mac 不需要公网地址，但要开着、不能睡眠。

## 设置

飞书开放平台检查长连接时，要求 Ollupi 已经连上，所以先填 Ollupi，再改订阅方式。

1. 在[飞书开放平台](https://open.feishu.cn/app)（Lark 用 open.larksuite.com）创建**企业自建应用**，在"添加应用能力"里加上**机器人**。
2. 在"凭证与基础信息"复制 App ID 和 App Secret，填到 Ollupi 的 **设置 → 飞书机器人**，点 **保存并重启**。
3. 在"权限管理"开通：
   - 读取用户发给机器人的单聊消息（`im:message.p2p_msg:readonly`）
   - 以应用的身份发消息（`im:message:send_as_bot`）
4. 在"事件与回调"中：
   - 事件配置：订阅方式选**使用长连接接收事件**，添加事件"接收消息"（`im.message.receive_v1`）
   - 回调配置：订阅方式选**使用长连接接收回调**，添加回调"卡片回传交互"（`card.action.trigger`）
5. 在"版本管理与发布"创建版本并发布，可用范围只选你自己就够。
6. 在飞书里搜到这个机器人，给它发一条消息。它会回复你的 open_id，把它填进 **为谁操作**，再保存一次。

也可以直接写 `~/.ollupi/config.yaml`：

```yaml
feishu:
  app_id: cli_xxx
  app_secret: xxx
  users: [ou_xxx]
  workspace: /path/to/project # 新会话所在的工作区，要先在桌面端添加；不写则不属于任何工作区
  # domain: lark              # 用 Lark 时
```

## 使用

- **开始会话**：在和机器人的单聊里直接发一条消息。机器人在这条消息下开一个话题，会话就在这个话题里。
- **桌面端的会话**：在桌面端或由定时任务开始的会话也会同步过来。它第一次开始一轮、或有审批和提问时，机器人发一条写着"工作区 · 标题"的消息，会话就在这条消息下的话题里，之后和从飞书开始的会话一样。以前的会话在下次有新的一轮时才出现。名单里有好几个人时，发给第一个人。
- **接着说**：在话题里回复。如果当前一轮还没跑完，这条消息会排队，等这轮结束后再开始。
- **停止**：点这一轮卡片上的 **停止**，或在话题里发 `/stop`。
- **进度**：每一轮一张卡片，代理的回复和它调用的工具会陆续追加上去。在桌面端或由定时任务发起的轮次会注明来源。
- **审批和提问**：会单独发一张卡片（子代理的也一样），点按钮审批，或者填好答案后提交。"总是允许"要写规则，只能在桌面端操作。在飞书和桌面任意一端处理后，卡片会更新成处理结果。

只处理单聊和名单里的人，目前只能发文字（包括富文本消息里的文字）。代码和对话内容会经过飞书的服务器。
