# ollupi desktop 设计需求

给交互设计对话的需求说明。要的产出是**设计思想、设计语言和设计准则**，不是逐屏的效果图：开发会按这些准则改写所有界面，并且以后新增界面时照着用。

## 产品是什么

ollupi desktop 是 ollupi（一个 Go 写的个人 agent）的桌面客户端，形态类似 Codex / Claude 桌面端。用户在本机的项目文件夹（workspace）里和 agent 对话，agent 会读写文件、跑命令、调用 MCP 工具、记住用户的偏好，必要时停下来请用户批准或回答问题。

- 平台：macOS 桌面应用（Electron），窗口可缩放，常用宽度 1200–1600px。
- 用户：一个人在自己的电脑上用，懂技术，会长时间盯着它工作。
- 语言：界面文案是英文，用户和 agent 的内容大量是中文，两者常混排。
- 浅色、深色两套主题，跟随系统。

## 现在的问题

界面是边做功能边加的，从来没有统一设计过，所以：

- **同一类东西长得不一样。** 例如截图里的提问卡片整块是蓝色底、选中项是蓝色粗边框，审批卡片是黄色底，工具调用是没有底色的一行，计划又是另一种样式。它们都是"对话流里 agent 产出的一块内容"，却像来自不同的应用。
- **强调色用得太重。** 提问卡片的大面积蓝色，在一整页灰色调的对话里非常跳。
- **尺度没有体系。** 字号用了 10/11/12/13/14px、`text-xs`、`text-sm`、`text-2xl` 等七八种；圆角有 sm/md/lg/xl/2xl/full 六种；间距也是随手取的。
- **层级不清。** 什么时候用卡片、什么时候用一行文字、什么时候用折叠块，没有规则。

## 需要你给出的东西

请按下面的结构给出准则。每一条最好能落到具体的值或可判断的规则上，开发要能据此判断"这样做对不对"。

### 1. 设计思想

- 这个产品给人的感觉应该是什么（几个关键词，以及它们在取舍时意味着什么）。
- 信息的主次怎么排：对话内容、agent 的过程（推理、工具调用）、需要用户行动的东西（审批、提问）、系统信息（压缩、记忆载入、token 用量），各自应该多显眼。
- 克制与强调的原则：颜色、粗体、底色、边框什么时候能用。

### 2. 设计语言（基础尺度）

现有的实现是 Tailwind v4 加一套语义 token（见文末），准则最好以同样的形式给出，开发直接替换 token 的值、收敛用法：

- **颜色**：中性色的层级（画布、侧栏、表面、浮层、悬停、分隔线，以及文字的主、次、弱三档），一个强调色，成功、警告、危险三种状态色，各自的使用场合。浅色和深色两套值。
- **字体与字号**：一套有限的字号阶梯（每级的字号、行高、字重），以及每一级用在哪里。中英文混排和等宽字体（代码、命令、路径）怎么处理。
- **间距**：间距阶梯，以及组件内、组件间、区块间分别用哪一档。
- **圆角、边框、阴影**：各有几档，分别用于什么。
- **图标**：现在用的是 lucide，尺寸和颜色的规则。
- **动效**：展开、出现、流式输出、加载这几种状态要不要动效、用什么节奏。

### 3. 组件和模式的准则

不需要画出每个组件，但需要规则：一类东西用什么样式、状态怎么表达。

- **对话流里的块**：用户消息、agent 回复（Markdown、代码块、表格）、推理（"Thought for 3.8s"）、工具调用（命令、输出、退出码、文件改动）、子代理、计划、压缩标记、记忆载入。哪些是卡片，哪些是一行，哪些可折叠，折叠前后各显示什么。
- **需要用户行动的块**：审批（允许一次、本会话允许、拒绝，有"在沙箱外运行"这种更危险的情况）和提问（单选、多选、自由输入，可能一次问好几个）。它们怎么在对话流里足够醒目，又不破坏整体风格；危险程度怎么区分。
- **状态的表达**：进行中、等待用户、完成、失败、被拒绝；徽标（badge）、圆点、颜色各在什么时候用。
- **按钮**：主要、次要、幽灵、危险几种按钮各自的用途；一个区域里最多几个主按钮。
- **表单**：输入框、下拉框、开关、多行文本，字段的标签、提示和错误怎么摆。
- **列表与导航**：侧边栏（workspace 分组和会话）、竖排子标签（Memory 页的范围列表）、横排标签（Settings 页）。选中、悬停、悬停才出现的操作按钮。
- **浮层**：对话框、提示条（toast）、气泡提示，各自什么时候用。
- **空状态、加载、错误**的统一写法。
- **数据展示**：Context 面板里的用量条、数字、时间、token 数这类密集信息怎么排得清楚。

### 4. 文案的语气

按钮和提示怎么写：长度、大小写、语气，出错提示要说清楚什么。

## 需要覆盖的界面

准则要能套到这些界面上（不用逐个出图，但请确认规则覆盖到了）：

- **侧边栏**：新建会话、添加 workspace、按 workspace 分组的会话列表（悬停出现设置、归档、新建）、折叠的已归档分组、Memory、Settings、连接状态。
- **新会话页**：标题、workspace 和模型选择、输入框。
- **对话页**：顶栏（标题、workspace、状态、定时任务、权限、Context 面板开关）、对话流、输入框（运行中可以追加或停止）。
- **Context 面板**（右侧）：上下文用量条和组成（可展开）、最近一次调用、模型调用列表。
- **Memory 页**：左侧范围列表，右侧记忆开关、状态和记忆条目（编辑、移动、遗忘）。
- **Settings 页**：General、Models、MCP、Tools 四个标签页，里面有卡片列表和编辑对话框。
- **对话框**：定时任务、会话权限、workspace 设置、MCP 服务器、模型提供方。
- **后端启动失败页**、各种 toast。

## 约束

- 跟随系统的浅色和深色，两套都要好看。
- 信息密度偏高：这是一个长时间使用的工具，不是营销页面。
- 现有实现：Tailwind v4，组件只用语义 token（`bg-canvas`、`text-fg-muted`、`border-line` 等），一套主题就是一组变量值。准则以 token 和规则的形式给出最好落地。
- 不引入新的组件库，图标继续用 lucide。
